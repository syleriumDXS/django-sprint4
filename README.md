# Блогикум — финальный проект четвёртого спринта

Проект доработан на основе предоставленного django_sprint3_completed(2).zip.
Python 3.10–3.12, Django 5.1.1. Проверено на Python 3.12.

## Запуск в Windows (PowerShell или CMD)

Откройте терминал в распакованной папке `django-sprint4`, где лежит requirements.txt.
Виртуальное окружение активировать не требуется: команды явно используют его Python.

```powershell
py -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe blogicum\manage.py migrate
.\venv\Scripts\python.exe blogicum\manage.py loaddata db.json
.\venv\Scripts\python.exe blogicum\manage.py createsuperuser
.\venv\Scripts\python.exe blogicum\manage.py runserver
```

Откройте http://127.0.0.1:8000/; админка: http://127.0.0.1:8000/admin/.
Команда `loaddata` необязательна: она добавляет демонстрационные записи, категории,
местоположения и пользователей. Не запускайте её повторно поверх изменённых демоданных.
Создайте собственный аккаунт через регистрацию или `createsuperuser`.
Для остановки сервера нажмите Ctrl+C.

## Запуск в Linux/macOS

```bash
python3 -m venv venv
venv/bin/python -m pip install -r requirements.txt
venv/bin/python blogicum/manage.py migrate
venv/bin/python blogicum/manage.py loaddata db.json
venv/bin/python blogicum/manage.py createsuperuser
venv/bin/python blogicum/manage.py runserver
```

## Что реализовано

- Страницы ошибок 403 CSRF, 404 и 500.
- Регистрация, вход, выход, смена и сброс пароля через Django auth.
- Общедоступные профили и редактирование собственного профиля.
- Пагинация по 10 записей на главной, в профиле и категории.
- Изображения, создание, редактирование и удаление собственных публикаций.
- Отложенные публикации и скрытые записи доступны автору; публичная видимость
  проверяется при каждом запросе, отдельный планировщик не требуется.
- Комментарии от старых к новым, счётчики, редактирование и удаление автором.
- Подтверждение удаления перед POST; GET ничего не удаляет.
- Статичные страницы реализованы через TemplateView.
- Письма сохраняются в `blogicum/sent_emails/`, изображения — в `blogicum/media/`.
  Эти каталоги, база SQLite и виртуальное окружение исключены в .gitignore.

Дата в форме используется в часовом поясе проекта (`TIME_ZONE = 'UTC'`,
сохранён из предыдущего спринта). При необходимости локального времени измените
его на `Asia/Tomsk` перед вводом новых дат.

Категории и местоположения создаются администратором. В пользовательской форме
можно только выбрать существующие. Пользователь не может менять автора,
флаг модерации или права администратора через формы.

## Шаблоны и исходные тесты

Все 28 шаблонов и тесты из https://github.com/yandex-praktikum/django_sprint4
перенесены без изменений. Версия исходного репозитория:
`eed238b53e18b927ee451edf43b9ee53d0a36bc2`.

Добавлены только отдельные шаблоны подтверждения выхода и письма сброса пароля.
В Django 5 выход требует POST: штатная ссылка «Выйти» открывает страницу
подтверждения с CSRF-защищённой формой.

Шесть дополнительных smoke-тестов из архива третьего спринта адаптированы к
новому контексту `page_obj` и лимиту 10 записей вместо пяти.
Ещё 15 проверок находятся в `checks/test_regressions.py`.

## Проверки

Из корня проекта в Windows:

```powershell
.\venv\Scripts\python.exe -m pytest tests checks
.\venv\Scripts\python.exe -m flake8 blogicum --config setup.cfg
.\venv\Scripts\python.exe blogicum\manage.py check
.\venv\Scripts\python.exe blogicum\manage.py makemigrations --check --dry-run
```

Результат сборки: 46 тестов пройдено (25 исходных тестов четвёртого спринта,
6 адаптированных smoke-тестов, 15 дополнительных проверок).
Проверены загрузка изображения, запрет подмены автора и повышения привилегий,
доступ к скрытым публикациям, привязка комментария к посту, CSRF, регистрация,
запись письма сброса пароля в файл и подтверждение выхода.

Кастомные 404/500 показываются при `DEBUG = False`. Для локального запуска
оставлен `DEBUG = True`, при котором Django также раздаёт изображения.

## Перед сдачей

Перенесите содержимое этой папки в свой репозиторий четвёртого спринта,
сохранив его `.git`. Запустите проверки и отправьте изменения на GitHub.
Не добавляйте `venv`, `db.sqlite3`, `media` и `sent_emails`.

Публикация на GitHub, изменение видимости репозитория, создание Яндекс-документа
и отправка формы сдачи не выполнялись. В Яндекс-документе укажите своё ФИО,
учебную почту и ссылку на публичный репозиторий.
